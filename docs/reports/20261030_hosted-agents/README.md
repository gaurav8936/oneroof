# Hosted agents: local integration acceptance

Project LAB-AE-OPEN-AGENTS · 2026-10-30 · local implementation, no release/install claimed.

## Result

The packaged One Roof test app launched both Goose 1.57.0 and OpenCode 1.19.5 through AppModel → private preparation → LaunchPlan → roofd → supervised native PTY → Together AI / `zai-org/GLM-5.3-Flash`. Each returned a real opening response and remembered `orchard` in a follow-up in the same conversation. The installed app, its profile and its roofd were not replaced.

The actual Needs you screen detected a Goose permission request to run `pwd`. Its Deny action selected the native Deny option, and the open decision count returned from one to zero. Screenshots verified the command, Settings connection fields and both New session cards. Unknown prompts remain manual; OpenCode approval stays in its native terminal while Escape rejection is supported.

## Reproduce

1. Use a separate worktree and its own copied Vendor frameworks. Run `cd app && swift test`.
2. Prepare Python/PyYAML, the reviewed kit and both pinned binaries outside the synthetic repository. Use external credential references and small explicit phase/shared reservation ceilings.
3. Build an ad-hoc app with `ONEROOF_BUNDLE_OUT` pointing into private test output. Give its test copy a distinct bundle ID and sign that copy. Never replace `/Applications/One Roof.app` for testing.
4. Use `app/scripts/test/run-app.sh` with an empty synthetic SQLite/profile seed. The existing `plan` self-test action accepts a sixth connection-ID field for hosted agents. Launch one agent, capture its native reply, send a follow-up, then launch the other. Use `needs`, `answer deny`, `settingspane 2`, `newsession` and `snap` for permission/setup captures.
5. Assert actual assistant reply lines, not merely the marker text embedded in the opening. Assert matching agent identities and live session counts, no AppModel error, a recognized permission, native denial acknowledgement and decision clearance.
6. Reattach to a live holder; verify its PID and conversation stay the same and opening is not resent. Terminate only test processes; retain ledger counters and verify owned native PIDs are gone.
7. Run the standard functional app harness on the rebased code before release. Release, signing/notarization, install and installed-Mac verification follow the central One Roof release runbook only when authorized.

## Limits and remaining release work

No automatic paid routing or recurring hosted schedules are enabled. Hosted loops support one supervised round, not unattended auto-approve. Native transcript resume after a terminated process is not implemented; reopen of a still-live holder preserves its conversation, while relaunch starts a new one with retained budget.

Together has full interactive/app acceptance here. OpenRouter and Fireworks had earlier authenticated tool-call smoke tests; this does not claim full interactive acceptance on every provider/model combination. Fireworks prices require manual verification from its official model page. The Cost section remains a separate backlog project.

Local landing/rebase validation and standard functional harness results are appended below when complete. Nothing in this report means the installed app has this feature yet.

## Final acceptance

The final full suite passed 794 tests, including a daemon test proving stored OpenCode/Goose repeating schedules are refused before a launch or another paid message. The same refusal is enforced when scheduling through the app and when its foreground scheduler processes existing records. Explicit single-round manual loops remain available.

The standard packaged-app functional harness passed all 57 checks across 14 journeys, using an isolated synthetic profile with one archived terminal history row. An initial empty profile could not satisfy its history-resume check; copying an entire prior test store then introduced stale window/session selection. A clean one-row archived fixture satisfied the actual prerequisite without changing any test or product assertion. These earlier fixture failures are retained in the private logs.

This was a functional run on a locked screen; performance, comparison and simulator suites were not run, and no release-gate artifact or installed-app readiness is claimed. The actual hosted app journeys and permission UI were separately captured and checked. All owned synthetic native processes and private idle test daemons were stopped.
